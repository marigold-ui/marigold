A `<ListView>` shows a collection of items as rows in a list. Each row can carry its own controls, such as a `<Button>` or an `<ActionMenu>`, so users can act on an item without leaving the page.

Use it for collections people work through rather than pick from, like a notification feed or a list of uploaded files.

## Anatomy

<ListViewAnatomy />

- **List:** The container that holds all rows.
- **Item:** A single row representing one entry of the collection.
- **Text value:** The primary text of a row, authored with `<TextValue>`. A bare string works too.
- **Description:** Optional secondary text below the text value, like a timestamp or a file size. One per row, and it takes inline markup — combine several facts into one line (`Updated 3 days ago · 2.1 MB`).
- **Actions:** Optional trailing controls for the row. One `<Button>` or `<ActionMenu>`, or a `<ButtonGroup>` wrapping several — the group is **required** above one control, because each control claims the same cell and two of them stack. The trailing cell takes Button-family controls only; other trailing content, like a `<Badge>` or a status pill, has no slot yet and is placed by the grid wherever a cell happens to be free.

To emphasise part of a row's text, nest `<Text as="span">` inside `<TextValue>` or `<Description>` rather than adding a `<Text>` of its own:

```tsx
<ListView.Item id="deploy" textValue="Deploy succeeded">
  <TextValue>
    Deploy{' '}
    <Text as="span" weight="bold">
      succeeded
    </Text>
  </TextValue>
</ListView.Item>
```

## Usage

Reach for a `<ListView>` when the user works through a collection one entry at a time, acting on a row where it sits instead of opening it. Typical cases:

- **Notification and activity feeds**: a stream of events the user scans, then dismisses or mutes per row.
- **Resource lists**: files, documents, or team members, each with rename, share, and delete behind a row menu.
- **Connections and integrations**: linked accounts or services the user reviews and disconnects individually.

If a row exists to be picked rather than acted on, see [`<ListView>` vs. `<SelectList>`](#listview-vs-selectlist).

### Row actions

Keep the action users reach for most often visible as an icon button and group the rest behind an `<ActionMenu>`. More than two visible buttons per row turns the list into a wall of controls that competes with the text people are scanning.

Pick a glyph that says what happens to the row — `Archive`, `Check`, `BellOff`. An `X` means "close this" everywhere else in Marigold, and a row's action doesn't close anything. Rare or irreversible commands like deleting belong in the menu, as an `<ActionMenu.Item variant="destructive">`, not behind a one-click icon button.

### `<ListView>` vs. `<SelectList>`

Both render a stack of rich rows, but they answer different questions. A `<ListView>` presents a collection the user reads and acts on. A [`<SelectList>`](/components/form/selectlist) asks the user to pick from a set, and that choice becomes a form value.

<GuidelineTiles>

    <DontDescription>
      Don't use `<ListView>` for a choice that gets submitted with a form,

    </DontDescription>
  </Dont>

## Accessibility

- Arrow keys move focus between rows, `Tab` reaches the controls inside the focused row.
- Give the list an `aria-label`, or `aria-labelledby` when a heading nearby already names it.
- Set `textValue` on a row whose text isn't a plain string, screen readers use it as the row's accessible name.

`<Title>` normally renders a real heading. Inside a row it renders as a `<span>` instead, so a heading-like row doesn't add an entry to the page's heading outline.
