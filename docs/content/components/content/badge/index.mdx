A `<Badge>` is a content component. This component can be used to reflect status messages via a short note and a color.

## Anatomy

It consists of a container and the content can either be a text or an icon.

<BadgeAnatomy />

- **Container:** The pill-shaped area that carries the variant color.
- **Text:** A short label naming the status or category.
- **Icon:** An alternative to the text when the meaning is clear without words.

## Appearance

Badges use color to convey meaning at a glance. Choose the variant that matches the semantic intent of the status or label.

| Variant   | Description                                                      | When to use                                                                                                    |
| --------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `default` | Neutral badge with a subtle border. This is the default variant. | Labels or metadata without a specific status, like categories, counts, or version numbers.                     |
| `primary` | Badge in the brand color with high visual weight.                | Drawing attention to important labels that don't represent a status, like "Recommended", "Pro", or "Featured". |
| `success` | Green-tinted badge.                                              | Positive statuses like "Active", "Completed", or "Approved".                                                   |
| `warning` | Yellow-tinted badge.                                             | Cautionary statuses like "Pending", "Expiring", or "Needs review".                                             |
| `info`    | Blue-tinted badge.                                               | Informational statuses like "New", "Updated", or "In progress".                                                |
| `error`   | Red-tinted badge.                                                | Negative statuses like "Failed", "Rejected", or "Expired".                                                     |
| `admin`   | Outlined badge with admin-specific color.                        | Marking content visible only to admin users. [Learn more.](/patterns/layout/admin-master-mark)                 |
| `master`  | Outlined badge with master-specific color.                       | Marking content visible only to master users. [Learn more.](/patterns/layout/admin-master-mark)                |

## Usage

A `<Badge>` is a component used to provide information on new updates and notifications. It is used with other components and cannot be used alone. The content of a badge can be arbitrary, but it is preferred to use a string and/or a icon.

### Sizes

A badge at its default size is taller than a line of text, which is right when it sits _next to_ text — in a table cell, a card header, a list row.

Inside a line of text it is not. A default badge in the label of a `<Checkbox>`, `<Radio>` or `<Switch>` makes that line taller than the control beside it, and the control ends up sitting above the words it belongs to. Use `size="inline"` there: it is drawn to the height of a text line, so both the line and the control stay put.

```tsx
<Checkbox
  label="Enable early bird pricing"
  labelAdornment={
    <Badge variant="master" size="inline">
      Master
    </Badge>
  }
/>
```

### Text Label Length

The Badge is a simple and compact component for use in a limited space in the context of more complex components. When it includes a text label, make sure it fits into the dedicated space.
