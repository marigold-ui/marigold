The `<CommandPalette>` component opens a search field over a list of pages and actions. People press <kbd>⌘</kbd>+<kbd>K</kbd> (<kbd>Ctrl</kbd>+<kbd>K</kbd> on Windows and Linux) from anywhere in the app, type a few letters and press <kbd>Enter</kbd> to go to the top match. It suits power users who live in the keyboard and apps with more pages than a sidebar can show comfortably.

## Anatomy

A command palette consists of an optional trigger and the palette itself, which opens on an underlay. The palette holds a search field, the list of results grouped under titles, and a legend of the keys. When nothing matches or results are still loading, a message takes the place of the list.

<CommandPaletteAnatomy />

- **Trigger:** An optional button that looks like a search field, reads "Go to…" and shows the shortcut. The shortcut works without it.
- **Search field:** The header of the palette. It gets focus when the palette opens and shows an <kbd>Esc</kbd> hint, a clear button once there is a query, or a spinner while results load.
- **Group:** An optional title over related items, for example Pages and Actions.
- **Item:** A single page or action, with an optional icon and description.
- **Active row:** The row <kbd>Enter</kbd> runs. There is always one while there are results, marked with a ↵ hint.
- **List:** Holds the groups and items and scrolls when they don't fit.
- **Legend:** A footer listing the keys to navigate, select and close. It is built in and hidden on touch devices.
- **Underlay:** Dims the page behind the palette. Clicking it closes the palette.

The palette itself has no variants or sizes. Its items take the same variants as menu items.

| Variant       | Description                                       | When to use                                              |
| ------------- | ------------------------------------------------- | -------------------------------------------------------- |
| `default`     | Standard item. This is the default variant.       | Pages and regular actions.                               |
| `destructive` | Red item signaling a dangerous action.            | Irreversible or high-impact actions like "Delete event". |
| `master`      | Item with a lock icon in the master access color. | Actions reserved for Reservix employees (master access). |
| `admin`       | Item with a key icon in the admin access color.   | Actions reserved for developers (admin access).          |

See the [Admin- and Mastermark pattern](/patterns/layout/admin-master-mark) for guidance on access marks.

## Usage

Put everything people jump to often into one palette per app: pages, frequent actions such as "Create event", and records like an event or an order once the app loads them.

### Keyboard

| Key                                                      | Action                                                    |
| -------------------------------------------------------- | --------------------------------------------------------- |
| <kbd>⌘</kbd>+<kbd>K</kbd> / <kbd>Ctrl</kbd>+<kbd>K</kbd> | Opens the palette from anywhere, also inside text fields. |
| <kbd>↑</kbd> / <kbd>↓</kbd>                              | Moves the active row.                                     |
| <kbd>Enter</kbd>                                         | Runs the active row.                                      |
| <kbd>Escape</kbd>                                        | Clears the search, then closes the palette.               |

One row is always active while there are results, so <kbd>Enter</kbd> always does something. When the search changes, the first row becomes active again.

Letters typed into the search field stay in the palette. Shortcuts your app binds to single keys, for example "c" to create, don't fire while people type a query.

The shortcut also fires inside text fields, as it does in GitHub, Linear and Slack. If another handler already used the key, for example a rich-text editor that inserts a link on <kbd>⌘</kbd>+<kbd>K</kbd>, the palette leaves it alone. Change the key with `shortcut="j"`, or turn it off with `shortcut={false}` when your app already uses it.

### Filtering

By default the palette matches the query anywhere in an item's text and ignores case and accents, so "cafe" finds "Café". It keeps your groups and your order and highlights the matching text. Pass your own `filter` function for a different match, for example a fuzzy one.

An item's text is its plain-text label, also next to an icon. When the label is built from `<Text>` slots, for example with a description underneath, pass `textValue` so the item can still be found.

### Empty state

When nothing matches, the palette says so and suggests a different search. Before anyone types into an empty list, it asks them to type. Render `<CommandPalette.Empty>` to replace that message, for example to name what people can search for.

<ComponentDemo name="command-palette-empty" />

### Results from the server

To search records on the server, pass `filter={false}`, control the query with `inputValue` and `onInputChange`, and render `<CommandPalette.Loading>` while results load. The search field shows a spinner while it is rendered. Debounce the requests in your own code.

### Search prefixes

People who use the app every day often know a record by its number. A short prefix lets them jump to it directly: in the demo below, `e:1024` finds the event with number 1024. Everyone else keeps using the regular search, so the prefix speeds up experienced users without getting in anyone's way.

Read the prefix from the controlled `inputValue`, turn off the built-in filter while it is present and render the matching records. Show the prefix in the placeholder or the empty state, otherwise nobody finds out it exists. Keep the prefixes few and memorable, one letter per kind of record.

### Mobile behaviour

On small screens the palette opens as a tray from the bottom edge. The search field and the list reach the edges of the tray. The <kbd>⌘</kbd>+<kbd>K</kbd> and <kbd>Esc</kbd> hints and the legend are hidden on touch devices.

## Accessibility

The palette follows the [combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/). Focus stays in the search field while the arrow keys move a virtual focus through the list, so screen readers announce the active row and people can keep typing. The empty and loading states sit inside the list, where screen readers announce them.

The search field is the only Tab stop. The caret is its focus indicator, so the field has no extra ring. When the palette closes, focus returns to where it was.

## Research

Before building the palette we looked at cmdk (used by shadcn/ui and Vercel), Linear, GitHub, Raycast, Mantine Spotlight, macOS Spotlight and the React Aria command palette example.

- **Pattern:** every one of them pairs a search field with a list and keeps a row active, so <kbd>Enter</kbd> runs the top match. Marigold builds on React Aria's `Autocomplete` over a `Menu`, which gives the combobox behaviour above.
- **Name:** "command palette" is the term most apps and libraries use. "Command menu" stays for a plain `Menu` of actions next to a trigger, so the two don't get mixed up.
- **Filtering:** a "contains" match keeps the authored order and groups, which people can learn. Fuzzy ranking finds more but reorders the list on every key. We start with "contains" and leave fuzzy matching to a custom `filter`.
- **Search prefixes:** VS Code, PowerToys and Retool let people narrow the search with a short prefix. This follows the usability heuristic of offering accelerators to expert users while the regular path stays available to everyone else. The common weak spot is that people don't know the prefixes exist, which is why the pattern above names them in the placeholder. Marigold has no prefix API yet and leaves the parsing to the app until more than one app needs it.
- **Small screens:** the palette uses a tray for now. It moves to a bottom sheet together with the other overlays once that component exists.
