feat(DST-1625): track `search_docs` MCP tool usage in telemetry so Insights can report call volume, unique callers, error rate, and top-searched doc topics. The event schema is now a discriminated union over `cli_command` and `mcp_tool_call`, and the rate-limit/persist logic moves into `api/telemetry/record.ts` so the MCP route can record in-process instead of the server POSTing to itself. Callers are identified only by an HMAC-SHA256 digest of their Keycloak `sub` (`MCP_TELEMETRY_HASH_SECRET`), never the raw claim, and the public `POST /api/telemetry` endpoint accepts CLI events only.

Consumer-visible for anything reading the telemetry store: events no longer go into per-day `telemetry:YYYY-MM-DD` lists but into a single `telemetry:events` stream, appended with `XADD` and read with `XRANGE`. Stream ids are `<epochMillis>-<seq>`, so any time window is one command rather than one `LRANGE` per day, and each entry carries the JSON event in a field named `data`. `mcp_tool_call` entries are interleaved with `cli_command` ones, discriminated on `event`. The stream is trimmed with `MINID ~` at roughly 200 days, where the daily lists had no expiry at all. Existing data in the old daily lists is not migrated and is no longer read by anything. Rate-limit keys also gain a source prefix (`telemetry:rl:{id}:{date}` → `telemetry:rl:cli:{id}:{date}`), which resets in-flight CLI quotas once on deploy and orphans the old keys until their ≤24h TTL expires.
